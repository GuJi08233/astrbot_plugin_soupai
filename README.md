# AstrBot 海龟汤推理游戏插件

一个为 AstrBot 开发的 AI 海龟汤推理游戏插件，通过调用 AstrBot 的 LLM 服务商实现自动生成谜题、接收用户提问、智能判断是否猜中故事等功能。

## 🌟 插件亮点

- ✅ **功能齐全**：支持游戏创建、智能问答、完整推理验证、提示引导、题库管理等完整流程
- 🌐 **网络题库支持**：内置 **188 道**去重后的海龟汤题面，覆盖多种题材与风格
- 🧠 **智能提示系统**：结合全部提问记录生成方向提示，基于 allow_list 限制名词，引导玩家理清思路


## 🎮 功能特性

- **智能谜题来源** - 支持网络题库、本地存储库与 LLM 现场生成，可通过策略设置优先级
- **自动生成与存储** - 本地存储库剩余题数低于阈值时自动补充新故事（可关闭），并持久化存储备用题库
- **难度与提问/提示限制** - 简单/普通/困难/666开挂了四种难度，对应不同的提问次数与提示次数限制
- **智能问答系统** - 使用 LLM 判断用户提问并回复“是/否/是也不是/不重要”
- **验证系统** - 使用 LLM 验证用户提交的完整推理结果
- **提示系统** - 使用 LLM 根据问答历史生成方向性提示
- **题库使用记录** - 记录题目使用情况，可查看并重置
- **题库标注与查重** - 按需提取题材、标签、故事因果和反转；新增及编辑入库前跨三个题库查重，支持可选嵌入模型与重排模型
- **会话控制与超时机制** - 每个群一次仅允许一个游戏，且游戏超时自动结束
- **管理员功能** - 强制结束、备用故事管理与题库管理等实用指令
- **用户友好界面** - 清晰的状态显示、次数限制提示和操作指引

## 🖥️ 网页管理

在 AstrBot 面板的插件页里打开「海龟汤管理」，可以：

- **题库** — 三个题库分栏浏览、搜索、分页；新增 / 编辑 / 删除；屏蔽某题使其不再被抽到；查看标注状态、单题标注或批量标注。**列表只显示汤面及标注状态，汤底和标注正文均需主动点击才会单独请求**
- **AI 生成** — 调用生成 LLM 现场出题（一次 1–5 道），可选配置默认题材、随机、日常悬疑、校园、职场、温情或自定义题材，并填写本次创作参考；通过查重后存入本地存储库
- **会话** — 每个群、每个私聊各自出过哪些题，可单独重置某个会话
- **对局** — 进行中的对局、提问/提示/验证次数、完整问答记录，可强制结束。每条问答标明判定来源，展开「Jev 判定详情」可查看各候选答案的概率、整体置信度及回退原因。这里同样不显示汤底
- **设置** — 直接在网页上改插件配置，和面板插件配置页是同一份。分别选择生成、问答判定、完整推理验证、提示及标注查重的 LLM，也可选择查重用的嵌入与重排服务商；调整默认题材、创作参考、判定引擎和出题策略等。**保存后立即生效，不需要重载插件**；Jev API Key 以密文处理，不回显，留空表示不修改

顶部「刷新」会更新当前标签的数据。「自动刷新（5 秒）」默认开启，可随时关闭，开关仅在本次页面中有效。自动刷新在页面隐藏、弹窗打开或已有请求时暂停，在设置页始终暂停；刷新对局时保留问答和判定详情的展开状态及滚动位置。

设置页切换标签后会保留未保存的修改，手动刷新前会先确认是否丢弃修改；请求期间继续编辑也不会被返回的数据覆盖。

网络题库是跟着仓库走的静态资源，网页端**只读**：想让某道题不再出现请用「屏蔽」，屏蔽名单存在插件数据目录，不会改动 `network_soupai.json`，也就不会在同步上游时冲突。

## 📚 题库标注与入库查重

**语义查重默认开启（`dedup_semantic_enabled: true`）。** 每次新增或编辑题目，在精确检查通过后，都可能额外调用标注与查重复核 LLM；选择了嵌入或重排模型时还会使用对应服务。网页生成、后台生成和手动新增共用这条入库流程，因此生成与保存可能比以前更慢。关闭该配置后仍会执行跨三个题库的精确检查，主动标注功能仍可使用。

### 查看和生成标注

标注包含 `theme`（题材）、`tags`（标签）、`summary`（完整故事摘要）、`causal_chain`（因果链）和 `twist`（关键反转）。**这些信息包含汤底。** 题库列表仅显示「未标注」「已标注」「标注已过期」；点击「查看标注」才会读取并展示正文，查看操作不会调用模型。点击单题的「LLM 标注」并确认后，才会生成该题的标注。

批量处理可在题库标签中点击「批量标注」：

1. 选择当前题库或全部题库，预览总数、已有有效标注数和待标注数；预览不调用模型。
2. 按需勾选「重新标注已有标注的题目」。默认跳过已有有效标注。
3. 点击「开始批量标注」后才启动任务，并展示进度、成功、失败、跳过数量和失败详情。
4. 弹窗打开时每 2 秒查询进度；关闭停止查询，任务仍会继续，再次打开可查看当前批次。点击「取消任务」可停止处理，已经完成并保存的标注会保留。

批量任务同一时间只运行一个。任务进度属于当前插件实例，重载后可以重新预览并启动，默认只处理缺失或失效的标注。题目内容变化会使旧标注失效；标注过程中若题目被编辑或删除，该次结果不会覆盖新内容。

标注和向量缓存保存在插件数据目录的 `story_catalog.json`，按题库、稳定题目 ID 与内容版本关联。网络题库也可标注，但不会修改仓库内的 `network_soupai.json`。仅打开管理页或批量预览不会自动标注现有题库；新题入库时的标注由语义查重配置控制。

### 入库前如何判重

- **精确检查**：跨网络、本地、自定义三个题库比较，忽略空白、标点和全半角差异。相同汤面和汤底、相同汤面却不同汤底、只更换汤面而保留相同汤底，都会被拒绝；编辑时排除该题自身。
- **候选召回**：语义查重开启时，先提取新题标注，再从已有题目的原文及有效标注中筛选相似候选。未配置嵌入模型时使用文字相似度，**措辞差异很大的改写可能漏检**，不能保证识别所有换皮题。
- **可选嵌入与重排**：首次选用嵌入模型进行查重时，会为题库建立向量缓存，耗时与调用量通常更多；后续复用相同模型和内容的缓存。重排模型进一步筛选候选，**重排分数表示相关性，不是重复概率**。
- **LLM 复核**：最终比较原始汤面、汤底中的人物关系、完整因果和关键反转；仅题材或场景相似不应算重复。缺少有效标注的旧题仍使用原文参与筛选，不要求先批量标注全库。

同批生成及并发保存共用 `save_story_checked()`，先检查再写入，后面的题目会与刚入库的题目继续比较。生成题目发生重复时，每道最多尝试 **3 次（含首次）**；**生成或查重失败不入库**，模型调用或返回格式错误会中止该题。批量生成中已经成功入库的题目会保留，其余失败会单独显示。手动新增或编辑被拒绝时，编辑器及输入内容会保留，便于修改后重试。

如果题目已经保存，但附带的标注缓存没有完整写入，页面会明确显示「已保存」及相应提示；这不属于保存失败，可稍后重新标注。

本地与自定义题库通过临时文件写入后替换原文件。新增、编辑或删除时若写入失败，会明确报错并恢复内存中的题目；本地库已满时也会保留原题和使用记录，避免失败的新题挤掉旧题。

## 📋 使用指令

### 基础指令

- `/汤` - 开始海龟汤游戏
- `/查看` - 查看当前已提问的问题及回答
- `/提示` - 获取方向性提示（参考当前所有提问与回答，有次数限制）
- `/验证 <推理内容>` - 验证用户对完整故事的推理（有次数限制，详见「验证系统」）
- `/揭晓` - 查看完整故事并结束游戏
- `/汤难度 <简单/普通/困难/666开挂了>` - 设置游戏难度（默认普通）
- `/汤状态` - 查看当前游戏状态
- `/备用状态` - 查看备用故事存储库状态
- `/汤配置` - 查看当前插件配置
- `/题库详情` - 查看本会话的出题记录（管理员）
- `/重置题库` - 重置**本会话**的出题记录；`/重置题库 all` 重置全部会话（管理员）

### 管理员指令

- `/强制结束` - 强制结束当前游戏（不会告知完整故事）
- `/备用开始` - 手动开始生成备用故事
- `/备用结束` - 停止生成备用故事
- `/重置题库` - 重置网络题库和本地存储库的使用记录
- `/题库详情` - 查看题库使用情况与已用索引

游戏中直接发送不带前缀的“强制结束”，同样要求 AstrBot 管理员权限。通过网页强制结束后可以立即开始新局，无需等待原对局超时。

## 🎯 游戏流程

1. **开始游戏** - 用户发送 `/汤`
2. **获取谜题** - 按策略从网络题库、本地存储库或 LLM 生成
3. **公布题面** - 题面发布到群聊并启动会话控制
4. **用户互动**
   - @机器人 + 任意陈述/问题（AI 回复：是、否、是也不是、不重要）
   - `/验证 <推理内容>` 验证完整推理过程
   - `/提示` 获取方向性提示（结合当前所有问答记录，有次数限制）
   - `/查看` 查看当前已提问的问题及回答
5. **游戏结束** - 用户输入 `/揭晓` 或验证成功时结束游戏

提问判定失败（模型不可用、超时或返回无效答案）不消耗提问次数，也不计入问答历史；Jev 回退到 LLM 并成功判定时正常计数。无限提问模式仍记录实际提问数。结束对局后，旧局迟到的判定、提示和验证结果不会再回复或影响新局。

## 🔍 验证系统

用户可以通过 `/验证` 指令验证自己的完整推理过程：

> 每局 `/验证` 的次数由配置项 `verification_limit` 决定（默认 2 次，填 0 表示不限）。该限制**全程生效**：不论提问次数是否用完，验证都会计数，用尽后再次验证会被直接拒绝，不会消耗 LLM 调用。
>
> 验证用尽时的处理分两种情况：若提问次数还有剩余，游戏继续，玩家可以接着提问或用 `/揭晓` 收场；若提问次数也已用完，则揭晓答案并结束本局。
>
> 猜错时只会返回等级和一句方向性反馈，**不会**返回模型对推理的详细点评——那类点评为了说清"哪里错了"必然复述谜底，等同剧透。详细点评仅在猜中、本局结束后给出。

- **完全还原**：推理与标准答案高度一致，包括核心逻辑与关键细节
- **核心推理正确**：推理的大方向或关键反转已覆盖，但部分细节有出入
- **部分正确**：理解了部分情节或动机，但因果链不完整
- **基本不符**：推理与真相严重不符

在 `简单` 难度下，"完全还原"或"核心推理正确"均视为猜中；其他难度需要达到"完全还原"才算猜中。

## 💡 提示系统

用户可以通过 `/提示` 指令获取方向性提示：

> 不同难度对应不同的提示次数限制：
> - **简单**：10 次提示
> - **普通**：5 次提示  
> - **困难**：1 次提示
> - **666开挂了**：无提示

提示系统会根据玩家此前的所有提问记录和已给出的提示，结合题面构建允许名词列表（allow_list），在此基础上生成不重复的方向性引导，帮助玩家调整思考方向。提示内容不会包含故事情节、动机、行为或结局的具体信息，仅围绕提问角度、方向、范围进行结构性引导，并以“关注【维度】：动词+对象/变量”的格式给出。提示次数用完后将无法继续使用。

## 🔧 技术特性

- **LLM 集成** - 使用 AstrBot 的 Provider 接口调用大语言模型，支持生成、判断和提示功能
- **独立 LLM 配置** - 支持分别配置生成谜题、判断问答、验证答案、生成提示及标注查重的 LLM；验证和提示留空跟随判断模型，标注查重留空依次跟随验证模型、判断模型
- **题库与存储** - 网络题库与本地存储库结合，支持自动生成、持久化和使用记录
- **会话管理** - 基于群聊的会话控制，支持多用户参与和指令处理
- **验证系统** - 智能验证用户推理的准确性和完整性
- **提示系统** - 基于问答历史生成方向性提示，帮助玩家调整思考方向
- **错误处理** - 完善的异常处理和边界情况处理
- **用户体验优化** - 智能提示、状态反馈和操作引导
- **数据持久化** - 保存题目、会话出题记录、屏蔽名单，以及旁路标注和向量缓存

## 📦 依赖要求

- AstrBot >= 4.16，< 5
- 已配置 LLM 服务商（用于生成谜题、判断问答、验证答案和生成提示）

## 🚀 安装使用

1. 将插件放置在 `AstrBot/data/plugins/` 目录下
2. 在 AstrBot WebUI 的插件管理处启用插件
3. 在插件配置页面设置 LLM 提供商和其他参数
4. 确保已配置 LLM 服务商，按需为生成、判断、验证和提示选择不同模型
5. 在群聊中使用 `/汤` 开始游戏

## ⚙️ 配置说明

插件支持以下配置项：

- **生成谜题的 LLM 服务商** - 从 AstrBot 已配置的对话模型中下拉选择（留空使用系统默认）
- **判断问答的 LLM 服务商**（`judge_llm_provider`）- 用于判断用户问答及 Jev 回退，适合响应较快的模型；留空使用当前会话模型
- **验证答案的 LLM 服务商**（`verify_llm_provider`）- 独立选择 `/验证` 使用的完整推理验证模型，适合推理能力较强的模型；留空跟随判断问答的 LLM 服务商，后者也留空时使用当前会话模型
- **生成提示的 LLM 服务商**（`hint_llm_provider`）- 独立选择 `/提示` 使用的模型；留空时跟随判断问答的 LLM 服务商
- **默认出题题材**（`generation_theme`）- 默认 `随机`；也可填写日常悬疑、校园等自由文本，最多 120 字。后台生成及未指定本次题材的生成使用此项
- **默认创作参考**（`generation_ideas`）- 默认留空，最多 2000 字。可填写人物、场景、线索或创作限制；网页生成填写的非空参考覆盖本次默认值，留空则沿用配置
- **题库标注与查重复核的 LLM 服务商**（`annotation_llm_provider`）- 用于结构化标注与相似故事复核；留空依次跟随 `verify_llm_provider`、`judge_llm_provider`。都留空时，聊天命令使用当前会话模型，网页及后台任务使用系统默认模型
- **入库时进行语义查重**（`dedup_semantic_enabled`）- 默认开启，可能增加模型调用；关闭后仍检查三个题库中相同汤面或汤底
- **题库查重的嵌入服务商**（`dedup_embedding_provider`）- 可选，从已配置的嵌入模型中选择；留空使用文字相似度召回，首次选择模型后会建立向量缓存
- **题库查重的重排服务商**（`dedup_rerank_provider`）- 可选，从已配置的重排模型中选择；留空不重排，重排结果只用于候选排序，最终重复判断仍由 LLM 完成
- **游戏超时时间** - 游戏超时时间（秒）
- **存储库最大容量** - 存储库最多保存多少个备用故事（默认 50）
- **自动补充题库**（`auto_generate_enabled`）- 默认开启；后台每 5 分钟检查一次本地存储库，剩余未出题数低于阈值就自动生成新题补满，关闭后只能手动生成
- **自动补充的剩余题数阈值**（`auto_generate_min`）- 剩余未出题数低于此值时自动补充，默认 10，填 0 等于不自动补充
- **谜题来源策略** - `network_first`（网络题库→本地存储库→LLM）、`local_first`（本地存储库→网络题库→LLM）、`custom_first`（自定义题库→本地存储库→LLM）、`random`（随机选择）
- **回复方式** - `quote` 引用提问者的原消息后再回答，多人同时提问时能分清在回答谁（默认）；`direct` 直接回复不引用。平台不支持引用时自动降级为直接回复
- **每局验证次数上限** - 每局最多可使用多少次 `/验证`，默认 2，填 0 表示不限
- **提问判定引擎** - 见下节。默认 `llm`

配置修改后需要重载插件生效。**在网页管理页的「设置」标签里保存则立即生效**，不需要重载。

## ⚡ 提问判定引擎（可选 Jev）

回答提问本质上是「从是/否/不重要/是也不是里挑一个」，可以交给 [TypeSafe](https://docs.typesafe.ai) 的 Jev 模型——它只返回你预先定义的选项，不可能跑题，响应约 0.7 秒，且每次判定附带置信度。

**只有提问判定可切换引擎，其余环节一律由 LLM 处理：**

| 环节 | 引擎 |
| --- | --- |
| 提问判定（是/否/不重要/是也不是） | 判断问答 LLM 或 Jev，可选 |
| `/验证` 提交答案 | **始终使用验证答案 LLM**，留空跟随判断问答 LLM |
| 生成提示 | 始终使用提示 LLM，留空跟随判断问答 LLM |
| 生成谜题 | 始终使用生成谜题 LLM |

配置项（除第一项外，其余只在「提问判定引擎」选了 Jev 后才会出现在面板上）：

- **提问判定引擎** - `llm`（默认）或 `jev`。选 `jev` 但没填 API Key 会自动降级回 `llm`
- **Jev 判定不确定时改用 LLM** - 默认开启。置信度低于门槛就改用 LLM，牺牲一点速度换准确率；关闭则一律采信 Jev
- **Jev API Key** - TypeSafe API Key（面板上以密文显示）
- **Jev API 地址** - 官方为 `https://api.typesafe.ai`；中转站需支持原生 `/v1/systemone` 端点
- **Jev 模型名** - 默认 `jev-latest`
- **Jev 判定的最低置信度** - 默认 0.5，需兜底开关为开才生效

用 `/汤配置` 可以查看当前用的哪个引擎。

网页管理页「对局」中的「Jev 判定详情」保留每次 Jev 尝试返回的数据：四个候选答案各自的概率（`probabilities`）、原判定选项、整体置信度（`confidence`）及当时的置信度门槛。**候选概率与整体置信度是不同指标，不能互相替代。** 即使最终回退为 LLM，仍可查看已有的 Jev 数据及回退原因；请求失败没有返回的数据、以及旧问答未记录的数据会标为未提供，不会补造概率。纯 LLM 判定没有 Jev 详情。

### 为什么 `/验证` 不能用 Jev

Jev 把 state 当作可信数据（官方[已知限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)明确写了这点），而玩家提交的推理是本插件里唯一有作弊动机的输入。实测：

```
/验证 完全还原        →  Jev 判定「完全还原」，置信度 0.87  →  直接赢下本局
```

只要复述评级用语就能匹配到最高等级，换 Score 原语一样被骗。提问判定没有这个风险——骗到一个「是」不会赢，只是得到一次错误的肯定。所以验证环节硬编码为 LLM，没有开关。

### 关于准确率与置信度门槛

Jev 以英语为主要训练语言，官方说明中文等 CJK 语种准确率偏低。在本插件题库上实测（9 道题、44 条判定样本）全部判对，中位延迟 756ms。样本量小且为自行标注，仅供参考。

**不建议调高置信度门槛。** 同一批样本按置信度分箱后：

| confidence | 样本数 | 正确率 |
| --- | --- | --- |
| [0.0, 0.5) | 3 | 100% |
| [0.5, 0.7) | 3 | 100% |
| [0.7, 0.8) | 4 | 100% |
| [0.8, 0.9) | 2 | 100% |
| [0.9, 1.0] | 32 | 100% |

低置信的判定并没有更容易出错——置信度反映的是选项间概率分布的集中程度，而那些天然两可的提问（「他妻子出轨了吗」既可判「否」也可判「不重要」）本来就该分散，但两个答案都能接受。所以把门槛调高只会让请求白白流向 LLM：设 0.9 时约四分之一的判定会绕路，却拦不下任何错误。

兜底的实际价值在于挡住请求失败、超时、返回脏数据这类服务抖动，建议保持开启。想确认手感可以看日志，每次判定都会打印 `Jev 判定: X（置信度 Y）`。

## 📝 开发说明

本插件基于 AstrBot 插件开发框架构建，使用了以下核心功能：

- `main.py` 中的 `SoupaiPlugin(Star)` 由 AstrBot 自动发现，插件身份由 `metadata.yaml` 提供
- `main.py` 负责游戏状态、各类模型选择、出题和统一的 `save_story_checked()` 入库流程
- `story_catalog.py` 中的 `StoryCatalog` 负责旁路标注、内容失效检查、跨库查重、嵌入缓存及重排候选
- `webui.py` 提供网页 API 和批量标注任务；`pages/dashboard/` 提供无需单独构建的管理页面
- `@filter.command` 注册指令处理器
- `session_waiter` 实现会话控制
- `_resolve_provider(provider_id, umo)` 统一选择 LLM，并保留当前会话的模型隔离
- `self.game_state.start_game()` 支持提示次数初始化

在插件目录使用 AstrBot 的 Python 环境运行测试：

```bash
python -m unittest discover -s tests -p 'test_*.py'
```

测试使用模型替身和临时数据，不需要真实 API Key。后台运行测试时，将单次进程的最长执行时间设为 60 秒。
