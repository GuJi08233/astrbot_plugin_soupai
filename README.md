# AstrBot 海龟汤推理游戏插件

一个为 AstrBot 开发的 AI 海龟汤推理游戏插件，通过调用 AstrBot 的 LLM 服务商实现自动生成谜题、接收用户提问、智能判断是否猜中故事等功能。

## 🌟 插件亮点

- ✅ **功能齐全**：支持游戏创建、智能问答、完整推理验证、提示引导、题库管理等完整流程
- 🌐 **网络题库支持**：内置 **188 道**去重后的海龟汤题面，覆盖多种题材与风格
- 🧠 **智能提示系统**：结合全部提问记录生成方向提示，基于 allow_list 限制名词，引导玩家理清思路


## 🎮 功能特性

- **智能谜题来源** - 支持网络题库、本地存储库与 LLM 现场生成，可通过策略设置优先级
- **自动生成与存储** - 在指定时间段自动生成新故事并持久化存储备用题库
- **难度与提问/提示限制** - 简单/普通/困难/666开挂了四种难度，对应不同的提问次数与提示次数限制
- **智能问答系统** - 使用 LLM 判断用户提问并回复“是/否/是也不是/不重要”
- **验证系统** - 使用 LLM 验证用户提交的完整推理结果
- **提示系统** - 使用 LLM 根据问答历史生成方向性提示
- **题库使用记录** - 记录题目使用情况，可查看并重置
- **会话控制与超时机制** - 每个群一次仅允许一个游戏，且游戏超时自动结束
- **管理员功能** - 强制结束、备用故事管理与题库管理等实用指令
- **用户友好界面** - 清晰的状态显示、次数限制提示和操作指引

## 🖥️ 网页管理

在 AstrBot 面板的插件页里打开「海龟汤管理」，可以：

- **题库** — 三个题库分栏浏览、搜索、分页；新增 / 编辑 / 删除；屏蔽某题使其不再被抽到。**列表只显示汤面，汤底要点一下「查看汤底」才会单独请求**，翻题库时不会被剧透
- **AI 生成** — 调用你配置的生成 LLM 现场出题（一次 1–5 道），直接入本地存储库
- **会话** — 每个群、每个私聊各自出过哪些题，可单独重置某个会话
- **对局** — 进行中的对局、提问/提示/验证次数、完整问答记录，可强制结束。这里同样不显示汤底
- **设置** — 直接在网页上改插件配置，和面板插件配置页是同一份。下拉选择 LLM 服务商、切换判定引擎（Jev 相关项会随引擎选择显隐）、调整超时/策略等。**保存后立即生效，不需要重载插件**；Jev API Key 以密文处理，不回显，留空表示不修改

网络题库是跟着仓库走的静态资源，网页端**只读**：想让某道题不再出现请用「屏蔽」，屏蔽名单存在插件数据目录，不会改动 `network_soupai.json`，也就不会在同步上游时冲突。

## 📋 使用指令

### 基础指令

- `/汤` - 开始海龟汤游戏
- `/查看` - 查看当前已提问的问题及回答
- `/提示` - 获取方向性提示（参考当前所有提问与回答，有次数限制）
- `/验证 <推理内容>` - 验证用户对完整故事的推理（有次数限制，详见「验证系统」）
- `/揭晓` - 查看完整故事并结束游戏
- `/汤难度 <简单/普通/困难/666开挂了>` - 设置游戏难度（默认普通）
- `/汤状态` - 查看当前游戏状态
- `/备用状态` - 查看备用故事存储库状态
- `/汤配置` - 查看当前插件配置
- `/题库详情` - 查看本会话的出题记录（管理员）
- `/重置题库` - 重置**本会话**的出题记录；`/重置题库 all` 重置全部会话（管理员）

### 管理员指令

- `/强制结束` - 强制结束当前游戏（不会告知完整故事）
- `/备用开始` - 手动开始生成备用故事
- `/备用结束` - 停止生成备用故事
- `/重置题库` - 重置网络题库和本地存储库的使用记录
- `/题库详情` - 查看题库使用情况与已用索引

## 🎯 游戏流程

1. **开始游戏** - 用户发送 `/汤`
2. **获取谜题** - 按策略从网络题库、本地存储库或 LLM 生成
3. **公布题面** - 题面发布到群聊并启动会话控制
4. **用户互动**
   - @机器人 + 任意陈述/问题（AI 回复：是、否、是也不是、不重要）
   - `/验证 <推理内容>` 验证完整推理过程
   - `/提示` 获取方向性提示（结合当前所有问答记录，有次数限制）
   - `/查看` 查看当前已提问的问题及回答
5. **游戏结束** - 用户输入 `/揭晓` 或验证成功时结束游戏

## 🔍 验证系统

用户可以通过 `/验证` 指令验证自己的完整推理过程：

> 每局 `/验证` 的次数由配置项 `verification_limit` 决定（默认 2 次，填 0 表示不限）。该限制**全程生效**：不论提问次数是否用完，验证都会计数，用尽后再次验证会被直接拒绝，不会消耗 LLM 调用。
>
> 验证用尽时的处理分两种情况：若提问次数还有剩余，游戏继续，玩家可以接着提问或用 `/揭晓` 收场；若提问次数也已用完，则揭晓答案并结束本局。
>
> 猜错时只会返回等级和一句方向性反馈，**不会**返回模型对推理的详细点评——那类点评为了说清"哪里错了"必然复述谜底，等同剧透。详细点评仅在猜中、本局结束后给出。

- **完全还原**：推理与标准答案高度一致，包括核心逻辑与关键细节
- **核心推理正确**：推理的大方向或关键反转已覆盖，但部分细节有出入
- **部分正确**：理解了部分情节或动机，但因果链不完整
- **基本不符**：推理与真相严重不符

在 `简单` 难度下，"完全还原"或"核心推理正确"均视为猜中；其他难度需要达到"完全还原"才算猜中。

## 💡 提示系统

用户可以通过 `/提示` 指令获取方向性提示：

> 不同难度对应不同的提示次数限制：
> - **简单**：10 次提示
> - **普通**：5 次提示  
> - **困难**：1 次提示
> - **666开挂了**：无提示

提示系统会根据玩家此前的所有提问记录和已给出的提示，结合题面构建允许名词列表（allow_list），在此基础上生成不重复的方向性引导，帮助玩家调整思考方向。提示内容不会包含故事情节、动机、行为或结局的具体信息，仅围绕提问角度、方向、范围进行结构性引导，并以“关注【维度】：动词+对象/变量”的格式给出。提示次数用完后将无法继续使用。

## 🔧 技术特性

- **LLM 集成** - 使用 AstrBot 的 Provider 接口调用大语言模型，支持生成、判断和提示功能
- **双 LLM 分离** - 支持分别配置生成谜题和判断问答/提示的 LLM 提供商
- **题库与存储** - 网络题库与本地存储库结合，支持自动生成、持久化和使用记录
- **会话管理** - 基于群聊的会话控制，支持多用户参与和指令处理
- **验证系统** - 智能验证用户推理的准确性和完整性
- **提示系统** - 基于问答历史生成方向性提示，帮助玩家调整思考方向
- **错误处理** - 完善的异常处理和边界情况处理
- **用户体验优化** - 智能提示、状态反馈和操作引导
- **状态持久化** - 游戏状态、题库使用记录和提示次数持久化保存

## 📦 依赖要求

- AstrBot >= 4.16，< 5
- 已配置 LLM 服务商（用于生成谜题、判断问答和生成提示）

## 🚀 安装使用

1. 将插件放置在 `AstrBot/data/plugins/` 目录下
2. 在 AstrBot WebUI 的插件管理处启用插件
3. 在插件配置页面设置 LLM 提供商和其他参数
4. 确保已配置 LLM 服务商（推荐配置判断问答的 LLM 服务商以获得更好的提示效果）
5. 在群聊中使用 `/汤` 开始游戏

## ⚙️ 配置说明

插件支持以下配置项：

- **生成谜题的 LLM 服务商** - 从 AstrBot 已配置的对话模型中下拉选择（留空使用系统默认）
- **判断问答的 LLM 服务商** - 从 AstrBot 已配置的对话模型中下拉选择，用于判断用户问答和生成提示（留空使用系统默认）
- **游戏超时时间** - 游戏超时时间（秒）
- **存储库最大容量** - 存储库最多保存多少个备用故事（默认 50）
- **自动生成开始时间** - 每天自动生成备用故事的开始时间（小时，24 小时制，默认 3）
- **自动生成结束时间** - 每天自动生成备用故事的结束时间（小时，24 小时制，默认 6）
- **谜题来源策略** - `network_first`（网络题库→本地存储库→LLM）、`local_first`（本地存储库→网络题库→LLM）、`custom_first`（自定义题库→本地存储库→LLM）、`random`（随机选择）
- **回复方式** - `quote` 引用提问者的原消息后再回答，多人同时提问时能分清在回答谁（默认）；`direct` 直接回复不引用。平台不支持引用时自动降级为直接回复
- **每局验证次数上限** - 每局最多可使用多少次 `/验证`，默认 2，填 0 表示不限
- **提问判定引擎** - 见下节。默认 `llm`

配置修改后需要重载插件生效。**在网页管理页的「设置」标签里保存则立即生效**，不需要重载。

## ⚡ 提问判定引擎（可选 Jev）

回答提问本质上是「从是/否/不重要/是也不是里挑一个」，可以交给 [TypeSafe](https://docs.typesafe.ai) 的 Jev 模型——它只返回你预先定义的选项，不可能跑题，响应约 0.7 秒，且每次判定附带置信度。

**只有提问判定可切换引擎，其余环节一律由 LLM 处理：**

| 环节 | 引擎 |
| --- | --- |
| 提问判定（是/否/不重要/是也不是） | LLM 或 Jev，可选 |
| `/验证` 提交答案 | **始终 LLM** |
| 生成提示 | 始终 LLM |
| 生成谜题 | 始终 LLM |

配置项（除第一项外，其余只在「提问判定引擎」选了 Jev 后才会出现在面板上）：

- **提问判定引擎** - `llm`（默认）或 `jev`。选 `jev` 但没填 API Key 会自动降级回 `llm`
- **Jev 判定不确定时改用 LLM** - 默认开启。置信度低于门槛就改用 LLM，牺牲一点速度换准确率；关闭则一律采信 Jev
- **Jev API Key** - TypeSafe API Key（面板上以密文显示）
- **Jev API 地址** - 官方为 `https://api.typesafe.ai`；中转站需支持原生 `/v1/systemone` 端点
- **Jev 模型名** - 默认 `jev-latest`
- **Jev 判定的最低置信度** - 默认 0.5，需兜底开关为开才生效

用 `/汤配置` 可以查看当前用的哪个引擎。

### 为什么 `/验证` 不能用 Jev

Jev 把 state 当作可信数据（官方[已知限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)明确写了这点），而玩家提交的推理是本插件里唯一有作弊动机的输入。实测：

```
/验证 完全还原        →  Jev 判定「完全还原」，置信度 0.87  →  直接赢下本局
```

只要复述评级用语就能匹配到最高等级，换 Score 原语一样被骗。提问判定没有这个风险——骗到一个「是」不会赢，只是得到一次错误的肯定。所以验证环节硬编码为 LLM，没有开关。

### 关于准确率与置信度门槛

Jev 以英语为主要训练语言，官方说明中文等 CJK 语种准确率偏低。在本插件题库上实测（9 道题、44 条判定样本）全部判对，中位延迟 756ms。样本量小且为自行标注，仅供参考。

**不建议调高置信度门槛。** 同一批样本按置信度分箱后：

| confidence | 样本数 | 正确率 |
| --- | --- | --- |
| [0.0, 0.5) | 3 | 100% |
| [0.5, 0.7) | 3 | 100% |
| [0.7, 0.8) | 4 | 100% |
| [0.8, 0.9) | 2 | 100% |
| [0.9, 1.0] | 32 | 100% |

低置信的判定并没有更容易出错——置信度反映的是选项间概率分布的集中程度，而那些天然两可的提问（「他妻子出轨了吗」既可判「否」也可判「不重要」）本来就该分散，但两个答案都能接受。所以把门槛调高只会让请求白白流向 LLM：设 0.9 时约四分之一的判定会绕路，却拦不下任何错误。

兜底的实际价值在于挡住请求失败、超时、返回脏数据这类服务抖动，建议保持开启。想确认手感可以看日志，每次判定都会打印 `Jev 判定: X（置信度 Y）`。

## 📝 开发说明

本插件基于 AstrBot 插件开发框架构建，使用了以下核心功能：

- `@register` 装饰器注册插件
- `@filter.command` 注册指令处理器
- `session_waiter` 实现会话控制
- `async def generate_hint(puzzle, true_answer, qa_history, hint_history, allow_list)` 实现提示生成功能
- `self.context.get_using_provider()` 调用默认 LLM 服务
- `self.context.get_provider_by_id()` 调用指定的 LLM 服务商
- `self.game_state.start_game()` 支持提示次数初始化
